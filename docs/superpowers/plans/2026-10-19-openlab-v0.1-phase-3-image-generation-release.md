# OpenLab v0.1 — Phase 3 Image Generation and Windows Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Integrate one verifiably compatible, locally running image model behind a headless ComfyUI adapter, then ship a Windows test installer with real generation, safe cancellation, saved results and side-by-side comparison.

**Architecture:** The Phase-1 Rust supervisor owns the ComfyUI process and job lock; a vetted pinned API workflow and installed model manifest from Phase 2 drive image generation. React shows only relevant controls and real progress. SQLite stores each immutable model/workflow revision and media path; a validated output is published atomically.

**Tech Stack:** Phase 1–2 Tauri/React/Rust/SQLx foundation, ComfyUI HTTP/WebSocket API, pinned workflow JSON, Rust HTTP/WebSocket client, local files, Vitest, Rust integration fixtures, GitHub Actions Windows builds.

**Spec:** [OpenLab v0.1 foundation design](../specs/2026-10-18-openlab-v0.1-foundation-design.md)

**Prerequisites:** [Phase 1](./2026-10-19-openlab-v0.1-phase-1-desktop-supervisor.md) and [Phase 2](./2026-10-19-openlab-v0.1-phase-2-model-manager.md) completed and reviewed.

## Global Constraints

- Only the **Image / OpenPixel** workspace runs a model in v0.1. Audio/Voice & Sound and Video/Motion remain honest placeholders.
- First model candidate is **FLUX.2 klein 4B**, subject to independent validation of current license, source, immutable revision, workflow, backend dependencies, memory/performance and actual Windows 16 GB VRAM operation. If that gate fails, stop and obtain replacement-model approval; do not silently switch.
- ComfyUI is a headless, owned local backend; do not require a user to understand or edit node graphs to generate an image.
- The Rust supervisor's one global permit spans start, prepare, generate, unload/stop and process cleanup. Do not attach to an uncontrolled ComfyUI process that might be used concurrently outside OpenLab.
- Never claim a result succeeded until media is validated and stored; save original prompt, seed, dimensions, adapter version, pinned workflow checksum and exact model variant/revision.
- No cloud inference, no arbitrary custom-node code from downloaded weights, no LAN-exposed server, no unbounded local HTTP proxy, and no automatic model replacement.
- Test on Windows hardware is the only authority for actual GPU compatibility; GitHub CI cannot substitute for it.
- Each task follows failing test → verify red → minimal implementation → verify green → commit.

## Review Focus

1. **User selects a model requiring missing custom nodes:** Task 1 and Task 3 reject generation with an actionable message before loading a job.
2. **Unexpected ComfyUI output path / malicious filename:** Task 3 and Task 5 reject any response escaping managed output roots.
3. **Two rapid model selections during a running job:** Task 4 and Task 6 show a queued switch, never overlap owned engine instances.
4. **WebSocket disconnect during a generation:** Task 2 and Task 6 recover via bounded status query or fail the job, without publishing false success.
5. **History after installed checkpoint is deleted:** Task 5 still displays saved media and original revision, labeled not currently reproducible.

## Phase-3 / v0.1 release gate

No v0.1 completion claim until automated test suites, Windows installer startup, a real image generated on compatible hardware, sequential engine lifecycle, data persistence, recovery tests, and model update refusal are independently evidenced. Generated outputs, model files, and private prompts remain local by default. Failures or skipped hardware checks must be reported rather than converted to green statuses.
