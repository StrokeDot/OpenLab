# OpenLab v0.1 — Phase 1 Desktop and Supervisor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Deliver a launchable Windows Tauri application with the three workspaces, persistent local data, a testable Rust-managed single-engine scheduler, and a simulated generation flow.

**Architecture:** Tauri 2 exposes narrow typed commands to React/TypeScript. Rust owns SQLite, a global FIFO job scheduler, the adapter lifecycle, process cleanup, and persisted state. A deterministic FakeAdapter demonstrates job progress and recovery without GPU models.

**Tech Stack:** Windows 11, Tauri 2, React, TypeScript, Vite, Vitest/Testing Library, Rust stable, Tokio, SQLx SQLite, serde, tracing, cargo test, GitHub Actions.

**Spec:** [OpenLab v0.1 foundation design](../specs/2026-10-18-openlab-v0.1-foundation-design.md)

## Global Constraints

- One model at a time: one global permit spans engine/model prepare, generate, unload, and cleanup; never release it while an owned process may still hold a model.
- Image/OpenPixel is the only functional generation workspace in v0.1; Audio/Voice & Sound and Video/Motion are clearly labeled future integrations.
- Local-first Windows desktop app. No cloud inference, unapproved network operations, unrestricted shell access, or arbitrary model execution.
- Follow red–green–refactor for each task; commit each independently testable slice. Keep work on an isolated implementation branch created from the approved design (not \`main\`).
- The initial repository has only \`README.md\` plus approved design documents. Do not assume a pre-existing Tauri scaffold.
- Use stable dependency releases compatible with Tauri 2, lock exact versions at scaffold time, and document versions in \`docs/development.md\`; do not invent unverified dependency versions.
- For the Rust domain model, use \`JobStatus = Queued|Preparing|Running|Unloading|Succeeded|Cancelled|Failed|Interrupted\`; never publish a false successful result.
- Separate large model files/results from the SQLite DB; keep all persistent data beneath configured, platform-appropriate directories.
- This phase intentionally tests with a FakeAdapter; it does not claim real GPU generation.

## Review Focus

1. **Repeated clicks on Generate:** Task 7 test verifies separate queued jobs with a unique ID, no concurrent generation.
2. **Restart while a job is running:** Task 6 test proves nonterminal jobs become Interrupted without automatic rerun.
3. **Cancellation when an adapter ignores requests:** Task 6 test proves bounded cancellation, owned-process cleanup, and no lock leak.
4. **Disk/database path missing or read-only:** Task 3 test proves failure is reported without destroying previous data.
5. **Switch to Audio/Video while Image runs:** Task 2 and Task 7 tests prove workspace navigation doesn't start another engine.

## Phase-1 completion gate

A reviewer must confirm a working local desktop shell; three honest workspaces; a correct global one-engine simulation; persistent and recoverable jobs; fake engine progress/cancellation; migration safety; and passing reproducible checks. **Do not start Phase 2** if there is a known lock leak, corrupt DB migration, or uncontrolled owned-process cleanup. No real image generation is claimed in this phase.
